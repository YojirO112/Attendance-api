# REVIEW.md

Defects found in the starter `app/main.py`, how each shows up, and how this version fixes it.

| # | Where | What is wrong | How you'd notice it | How it is fixed |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds the shift start with `punch_in.replace(hour=h, minute=m)` on a UTC/naive datetime, so the shift start is 09:30 **UTC**, not IST. | Punch-in at 10:05 IST (04:35 UTC) gives a negative difference, so `late_minutes` is 0. A late employee is never late. | Shift start is built as an IST wall-clock time on the attendance date, then compared as aware datetimes (`_ist_wall_clock`, `compute_late_minutes`). |
| 2 | `compute_late_minutes` | Grace check works on whole minutes: `minutes > 10`. R2 says strictly more than 10:00. | 09:40:30 gives `int(10.5) = 10`, not `> 10`, so 0. It must be 10. 09:40:01 has the same problem. | Compared in seconds: `elapsed > 600`, then `elapsed // 60`. |
| 3 | `compute_late_minutes`, `punch_in` | Overnight shifts ignored. The date is the calendar day of the punch-in, and the shift start is taken on that same day. | Shift 22:00-06:00, punch-in 05:30 IST on the 7th: belongs to the 6th, but a record is created for the 7th. | `attendance_date` applies R1 (punch-in before `shift_end` on an overnight shift goes to the previous day). Lateness uses the shift start of that attendance date. |
| 4 | `compute_work_hours` | Uses float `round(x, 2)`, which is banker's rounding on binary floats. Instants are also not truncated to whole seconds. | 8 h 2 min 42 s is exactly 8.045 h and must report 8.05, but `round(8.045, 2)` returns 8.04. 8 h 7 min 30 s (8.125) gives 8.12 instead of 8.13. | Decimal arithmetic with `ROUND_HALF_UP` (`half_up`, `compute_work_hours`). Instants are truncated on input (`ms_to_dt`). |
| 5 | `compute_overtime` | No 30-minute minimum (R3). Overnight shift end is placed on the attendance day instead of the next day. Subtracts an aware value from a possibly naive `punch_out`. | Punch-out 10 minutes after shift end returns 10 instead of 0. Overnight 22:00-06:00, out 06:40 returns 0 instead of 40. A naive datetime from PyMongo raises `TypeError` (500). | `compute_overtime`: floor minutes, require >= 30, end moved by one day for overnight shifts. Client is `tz_aware=True`, and `as_utc` normalises anything stored. |
| 6 | module level `MongoClient` | Default client returns **naive** datetimes. Naive and aware values get mixed in arithmetic and in JSON output. | `can't subtract offset-naive and offset-aware datetimes` the moment `compute_overtime` runs on stored data. | `MongoClient(..., tz_aware=True)`; every conversion goes through `as_utc` / `dt_to_ms`. |
| 7 | whole file | No indexes at all, and nothing is created at startup. Uniqueness of `emp_code` and of (`emp_code`, `date`) is not enforced. | Every query is a COLLSCAN; `/admin/explain` cannot show IXSCAN; duplicate records are possible. | `ensure_indexes()` at startup (and retried from `/health`), idempotent, with explicit index names. |
| 8 | `GET /health` | Always returns ok, even when MongoDB is down. | Stop MongoDB: the probe still says 200, so the runner starts testing a dead service. | Pings MongoDB; 503 when it does not answer. Connection failures elsewhere are mapped to 503, not 500. |
| 9 | `POST /employees` | Check-then-insert (`find_one` then `insert_one`). | Two parallel creates of the same `emp_code` both pass the check and both insert, or one gets a 500 once a unique index exists. | Unique index plus `insert_one`; `DuplicateKeyError` becomes 409. |
| 10 | `POST /employees`, `EmployeeIn` | No validation: any `emp_code`, email, shift strings, `joined_on`; `shift_start == shift_end` allowed. `created_at = datetime.now()` is naive local time and is returned as an ISO string. | `shift_start: "25:99"`, `joined_on: "yesterday"` return 201. `created_at` differs from UTC by the server's offset. | Pattern and length constraints from the contract, real calendar-date check, shifts must differ (422). `created_at` is UTC and returned as epoch ms. |
| 11 | `GET /employees` | `skip = page * page_size` skips a whole page (page 1 starts at record 21). `total` counts the whole collection, ignoring `department`. No sort. No limits on `page` / `page_size`. | Page 1 of 25 employees returns 5 rows; `total` is 25 when filtered to 3. `page_size=100000` or `page=0` accepted. | `skip = (page - 1) * page_size`, `total = count_documents(filter)`, sorted by `emp_code`, `page >= 1`, `1 <= page_size <= 100` (R10). |
| 12 | `POST /attendance/punch-in` | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises `TypeError` -> 500. | `{"emp_code": "NOPE"}` returns 500 instead of 404. | `get_employee` raises 404 first. |
| 13 | `POST /attendance/punch-in` | `punched_at` is not validated and `fromtimestamp(ms / 1000)` uses the **server's local zone**; `if body.punched_at` treats 0 as missing; no truncation. | Seconds (1783312500), floats, strings and bools are accepted. Date depends on where the server runs. | `EpochMillis` is a strict int in `[1e11, 4.1e12]` (422 otherwise); conversion is UTC; date comes from R1 in IST. |
| 14 | `POST /attendance/punch-in` | `status` is free text. | `"status": "ABSENT"` or `"banana"` returns 201. | `PresenceStatus` literal (PRESENT / WFH / ON_DUTY). |
| 15 | `POST /attendance/punch-in` | Check-then-insert race. | 16 parallel requests: several 201s and duplicate records. | Unique (`emp_code`, `date`) index; `DuplicateKeyError` -> 409. |
| 16 | `punch_in`, `list_attendance` responses | Leak `_id` as `id`, and return BSON datetimes (ISO strings) instead of epoch ms. Legacy documents are returned without `half_day` / `history`. | Response has an `id` field that is not in the contract and `punch_in: "2026-07-06T04:35:00"`. | `record_out` builds the response: no ids, epoch ms everywhere (including inside `history`), defaults for missing fields. |
| 17 | `GET /attendance` | Loads the whole collection into memory (`list(find(q))`), sorts in Python, and slices. `page=0` gives a negative slice. Sort lacks the `emp_code` tie-break. No `date_from > date_to` check, `status` is not validated. | Slow and memory hungry at 100k records; `page=0` returns the wrong rows silently. | Database does the work: `find(...).sort(date desc, emp_code asc).skip().limit()` over index `(date desc, emp_code)`; validated parameters; 422 when `date_from > date_to`. |
| 18 | `GET /attendance`, `GET /employees` | Date filters accepted as arbitrary strings. | `date_from=banana` simply returns nothing instead of 422. | `IsoDate` type: pattern plus real calendar check. |
| 19 | missing endpoints | Punch-out, PATCH, the four analytics endpoints and `/admin/explain` do not exist. | 404 / 405 on every one of them. | Implemented (see README). |

## Looked at and left as is

* **`load_dotenv()` at import.** It does not override variables that are already set, so real environment variables win, which is what the contract asks for.
* **201 on create and punch-in, 409 message text, `{"detail": ...}` error bodies.** These match the contract.
* **`doc.pop("_id")` after `insert_one`.** `insert_one` adds `_id` to the dict, so popping it was right; the new code builds a separate output dict instead.
* **`history: []` and `half_day: False` on new records.** Correct per DATA_MODEL.
* **Default `shift_start` / `shift_end` in `EmployeeIn`.** Match the OpenAPI defaults.
